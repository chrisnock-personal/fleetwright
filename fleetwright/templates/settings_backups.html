Setting up backups

  1. On another machine, make a key: age-keygen -o fleetwright-backup.key. Keep that file, and a copy of FLEETWRIGHT_SECRET_KEY, off this server. An SSH key you already have works too.
  2. In .env, set BACKUP_AGE_RECIPIENTS to its public key (the age1… line, or the ssh-ed25519 … public key). Optionally BACKUP_AT (default 03:30 UTC), BACKUP_KEEP (14) and BACKUP_DIR (./backups).
  3. Start it: docker compose --profile backup up -d (or podman-compose --profile backup up -d). It makes a backup straight away. A backup on demand: docker compose --profile backup run --rm backup now.
  4. Copy the backup directory somewhere else as well: a backup on the same disk doesn't survive that disk.

Notification channels that include “A backup failed, or none has been made for over a day” hear about failures.

Restoring

On the new or repaired server, with FleetWright's files and the old .env (or at least its FLEETWRIGHT_SECRET_KEY): backup/restore.sh fleetwright-….tar.age fleetwright-backup.key. It replaces the database and the certificate with the backup's and starts FleetWright; agents reconnect by themselves.

Secret key

FLEETWRIGHT_SECRET_KEY encrypts the stored SSH keys and notification secrets. To change it, put the new key in FLEETWRIGHT_SECRET_KEY and the old one in FLEETWRIGHT_SECRET_KEY_PREVIOUS, and restart: FleetWright re-encrypts everything under the new key, then the old one can go from .env. Everyone has to sign in again. Keep the old key with your backups until the ones made before the change have expired: restoring one of those needs it in FLEETWRIGHT_SECRET_KEY_PREVIOUS.
